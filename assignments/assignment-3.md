## What you are submitting

Your work lives on **GitHub** (profile + profile README repo), not in a new code project. Before you submit, confirm:

- [ ] **Edit profile** — profile photo (or clean avatar), full name, **one-sentence bio** (not placeholder text), at least **one link** (website, LinkedIn, or portfolio)
- [ ] **Pinned repos** — at least **2** repos pinned; one must be **[goobolabs/git-github-bootcamp](https://github.com/goobolabs/git-github-bootcamp)** (the original bootcamp repo, not your fork)
- [ ] **Profile README** — public repo named exactly your username (`your-username/your-username`) with a `README.md` that renders on your profile
- [ ] **Activity overview** — enabled under **Contribution settings** on your profile (shows orgs/repos + contribution breakdown)
- [ ] **Quality skills list** — README lists tools you **use now** (see Bonus 8); no long redundant stack (e.g. do not list HTML, CSS, Bootstrap, Tailwind, JS, TS, React, Next.js, and every React library together)

### Profile README must include

- A short intro (who you are, what you build)
- Links to at least **2 projects** (e.g. [goobolabs/git-github-bootcamp](https://github.com/goobolabs/git-github-bootcamp), Assignment 2 repo, `git-github-practice`)
- A **Tech** or **Skills** section with a **short, honest** list (roughly **4–8 items**, one per layer — e.g. `TypeScript · Next.js · Git`, not every tool from every course)

### Example `README.md`

**Good:** short intro, real project links, **4 skills** (not HTML + CSS + Bootstrap + Tailwind + JS + TS + React + …).

**Your choice:** You may add whatever you like — extra sections, tables, images, even **animations** or ASCII art. GitHub does not restrict you.

**Keep it readable:** A profile README **longer than the sidebar** (photo, bio, links on the left) usually hurts more than it helps. Visitors scroll past pins and pinned repos before they see your work. Animations and huge widgets slow loading and distract from projects. Aim for **about sidebar height or less** — say who you are, link your best repos, move on.

**Avoid:** badge walls, 20+ technologies, placeholder links, repos you did not build, README taller than the sidebar.

## Common mistakes

| **Mistake** | **Fix** |
| ----------- | ------- |
| Profile README repo is private | Must be **public** |
| Repo name ≠ username | Profile README repo must be exactly `your-username/your-username` |
| Only README, empty sidebar | Fill **Edit profile** and pins too |
| `goobolabs/git-github-bootcamp` not pinned | Pin the **original** bootcamp repo — not your fork |
| Skills list with 20+ similar tools | **Quality over quantity** — TypeScript not JS+TS; Next.js not React + every library |
| README longer than sidebar | Trim it — visitors should see pins without scrolling past a huge README |
| Heavy animations or badge walls | Allowed, but keep subtle — projects and links matter more |
| Activity overview off | Profile → contribution graph → **Contribution settings** → enable **Activity overview** |
| Wrong URL in submission | Use your **profile** URL and **profile README repo** URL, not a random project repo |
| Submission folder name wrong | Folder must exactly match your GitHub username (case-sensitive) |
| Changing others' submissions | Only edit **your** folder under `submissions/<your-username>/` |

## Why this matters

Employers and OSS maintainers look at your **GitHub profile**, not just one repo. Contributions include **issues**, **PRs**, and **reviews** — not only commits. A complete profile plus ongoing OSS activity (see [Bonus 3](../bonus/03-open-source-contributing.md)) shows you collaborate, not just code alone.
